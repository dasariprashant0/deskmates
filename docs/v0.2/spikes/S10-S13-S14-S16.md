# Spikes S10, S13, S14 and S16 results (local scripts, no Claude sessions)

Run on 2026-10-19. Numbers only. Raw data: `S10-S13-S14-S16-results.json`. Plan: SPEC section 15.

Environment: macOS (Darwin 27.0.0), **Node v26.10.0, the only version installed**. Dependency-free scripts in a scratch folder; no Claude session started, nothing installed, `~/.claude` untouched. The machine was **heavily loaded** while S13 and S14 ran (load average about 20, because other Claude sessions were busy), so the timings below are pessimistic.

## Verdicts

| Spike | Verdict |
|---|---|
| S10 Unix socket transport | PASS |
| S13 hook cold start | FAIL as measured, under heavy load; the cost is Node's own start-up, so shrinking the script cannot fix it. Opened OQ24, decided (a) the same day: keep Node, budget p95 under 400 ms on an idle machine, idle re-measure pending |
| S14 hung server and the ack rule | PASS, with a thin margin |

## S10: a Unix socket from a dependency-free Node script

- **Round trip** (HTTP over the socket, a new connection per request, 200 requests after 10 warm-ups): p50 0.13 ms, p95 0.28 ms, p99 0.60 ms, max 0.66 ms. Far under the 50 ms bar.
- **Path length:** socket paths worked from 98 up to 200 bytes (checked at 100, 103, 104, 105, 110, 120, 150 and 200: the socket file exists at the full path and accepts a connection there) and failed with `EINVAL` at 300. The usual 104-byte macOS limit did not apply with this Node. The design's `~/.deskmates/run/ingest.sock` is 48 bytes for this user. Older Node versions and non-Node clients may still have the 104-byte limit, so the installer should keep the path under 104 bytes and `doctor` should warn otherwise.
- **Mode and owner checks:** with the directory at 0700 and the socket at 0600 the check passes. It reports a problem for a directory at 0755, a socket at 0666, a regular file in place of the socket, and a symlink in its place. The owner comparison (uid) is implemented, but a socket owned by another user cannot be created without privileges, so only the same-owner pass case was exercised.
- **Live and stale sockets (R55, R67):** a second server cannot bind while the first is alive (`EADDRINUSE`, and a probe-connect succeeds). After the first server is killed, a stale file remains, a probe-connect returns `ECONNREFUSED`, and unlinking then rebinding works. So "probe before unlink" distinguishes the two cases.
- **Consequence:** the Unix-socket ingest with `node:http` works as designed; OQ5 (a) stands.

## S13: hook cold start

100 runs per variant, through `sh -c` with the same `[ -x node ] && [ -r script ] && exec node script; exit 0` form as SPEC section 9, a 750-byte payload on stdin. Times in milliseconds, wall clock from spawn to exit.

| Variant | p50 | p95 | p99 |
|---|---|---|---|
| Node hook, server up (first run) | 163.5 | 347 | 607 |
| Node hook, server up (rerun) | 149.6 | 236 | 410 |
| Node hook, server absent (the fail-open path) | 158.9 | 267 | 323 |
| Baseline: `node -e ''`, runtime start only (first run / rerun) | 160.7 / 154.1 | 306 / 276 | 611 / 470 |
| Baseline: `node --version` | 148.5 | 391 | 538 |
| `python3 -c pass` (system python) | 54.5 | 116 | 166 |
| Guard false (script unreadable): `sh` only | 13.7 | 40.5 | 56 |
| `sh -c 'exit 0'` | 12.7 | 29.8 | 81 |

Every hook run exited 0 with empty stdout (0 of 300 non-zero or non-empty).

- The hook is as slow as an empty Node process: Node's own start-up is about 150 ms here, so the spec's "reduce the script" option cannot help. Against the 150 ms p95 bar the Node hook fails (p95 236 to 347 ms), but the load makes that a pessimistic read.
- Not measured: a `curl --unix-socket` hook, because a guard on this machine redirects any command mentioning that tool and I did not work around it; and a `nc -U` hook, which needs a raw protocol instead of HTTP.
- Context: the PermissionRequest hook runs only when Claude Code is about to show a permission dialog, not on every tool call, so an extra 150 ms lands on an event that is already waiting for a human.
- **Consequence:** OQ24 (runtime and budget) was decided (a) on 2026-10-19: keep Node and restate the budget as a p95 under 400 ms measured on an idle machine. That idle-machine re-measure is still to do, and it will show how much of the cost here was load.

## S14: a stopped server and the 500 ms ack rule

The stub hook client follows R60: 500 ms to connect, 500 ms for an ack line, then exit 0 with empty output.

| Phase | Result |
|---|---|
| Server up, 10 runs | acked 10 of 10; wall 129 to 164 ms |
| Server stopped with `SIGSTOP` (process state `T`), 20 runs | connect succeeded 20 of 20 (the kernel accepts into its backlog); no ack; exit 0 with empty stdout every time; wall 639 to 684 ms; under 700 ms in 20 of 20 |
| 300 simultaneous connections while stopped | 108 connected, 192 `ECONNREFUSED`: the macOS backlog holds 128 |
| 5 hook runs with the backlog full | `ECONNREFUSED` at once; exit 0 empty in 123 to 160 ms |
| After `SIGCONT`, 5 runs | acked 5 of 5; wall 129 to 133 ms |

- **Consequence:** R60 is confirmed: against a stopped server the connect still succeeds, so only an application-level ack detects it, and the hook then fails open.
- **Thin margin:** the 639 to 684 ms is the 500 ms ack plus about 130 ms of Node start, so only 16 ms below the 700 ms bar, and a slower start would exceed it. Worth a shorter ack deadline (about 350 ms) or measuring the budget from connect; to be settled together with OQ24.

## S16: the Node inspector and SIGUSR1

10 fresh processes per variant, `--inspect-port=0` to avoid port collisions (the default port was checked once separately).

| Variant | Inspector opened | Process survived |
|---|---|---|
| No protection | 10 of 10 (and the default port 9229 listened) | 10 of 10 |
| A `SIGUSR1` handler only | 0 of 10 | 10 of 10 |
| `--disable-sigusr1` only (the flag exists in 26.10) | 0 of 10 | 10 of 10 |
| `--disable-sigusr1` plus a handler | 0 of 10 | 10 of 10 |

- **Consequence:** the risk is real, and on this Node either measure closes it. Use the flag where it exists and a handler as well, and keep R70's rule that the server refuses control whenever `inspector.url()` is set. A start-up self-test (raise `SIGUSR1` on itself and check) would cover Node versions I could not test.
- **Not shown:** Node 20, 22 and 24 (not installed). The flag and the handler behaviour differ between versions.

## Caveats

One machine under heavy load, one Node version, one OS. The scripts used throw-away servers, not deskmates code.
