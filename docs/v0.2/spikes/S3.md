# Spike S3 results: our hook versus a second hook

Run on 2026-10-19. Numbers only; no transcript content. Raw per-trial data: `S2-S3-results.jsonl` (rows with `phase: "S3"`). Plan: `S2-S3-PLAN.md`.

Environment as in `S1.md`. Ours came through `--settings`; the second ("foreign") hook came from the scratch folder's `.claude/settings.local.json`, so the two sat in different scopes. Each returned none (no output), allow or deny. 65 sessions: the 3-by-3 matrix (5 runs per cell, both hooks answering immediately) plus forced-order runs for the two cells where they disagree. The allow stubs let `touch probe.txt` run in the scratch folder (approved); the file was set aside after each trial.

## Verdict: FAIL, under the spec's own criterion

The spec says: a defined, repeatable result in all nine cells, and a deny from either side is never overridden by our allow; otherwise control ships OFF regardless of what `doctor` can discover.

**The first hook to answer wins, whatever it says.** So an allow can beat a deny, and when both answer at about the same time the result is a race.

## The nine cells (5 runs each, both hooks answer immediately)

| Ours | Foreign | Outcome |
|---|---|---|
| none | none | dialog live, 5 of 5 |
| none | allow | command ran, 5 of 5 |
| none | deny | denied, 5 of 5 |
| allow | none | command ran, 5 of 5 |
| allow | allow | command ran, 5 of 5 |
| **allow** | **deny** | **command ran 3 times, denied 2 times** |
| deny | none | denied, 5 of 5 |
| **deny** | **allow** | **command ran 4 times, denied 1 time** |
| deny | deny | denied, 5 of 5 |

Every cell with at most one decider is deterministic: one decision is enough and it applies. The two conflicting cells are not.

## Forced order (5 runs per configuration, the slower hook answers 400 ms later)

| Ours | Foreign | Who answered first | Outcome |
|---|---|---|---|
| allow | deny | foreign (deny) | denied, 5 of 5 |
| allow | deny | ours (allow) | command ran, 5 of 5 |
| deny | allow | foreign (allow) | command ran, 5 of 5 |
| deny | allow | ours (deny) | denied, 5 of 5 |

20 of 20 runs: the decision of whichever hook answered first was applied. In the natural-race runs, wherever the millisecond timestamps show a clear earlier hook, the same rule explains the result; exact ties (same millisecond) went either way.

The slower hook was not cancelled in any of the 60 decided trials: no signal reached either hook, and the 400 ms hook ran to completion with its output ignored.

## What this means

- **A deskmates allow can override a user's own deny hook** if ours answers first. A foreign allow hook can likewise pre-empt a deskmates deny. Neither side gets priority, and deny does not beat allow.
- A human click usually takes seconds, so a fast automatic deny hook normally answers first, but a slow one (a hook that calls a service, for instance) can lose to a quick click, and the order is not something deskmates can control or promise.
- Consequence required by the spec: **control (browser approve and deny) ships OFF** until this changes. `doctor` cannot make it safe, because it cannot discover plugin and skill hooks (known gap). This is recorded as a new decision for the owner, OQ21 in SPEC section 14.
- Slice 1 (hook-based Needs-you, no decide) is unaffected: its hook only ever returns no opinion (R69).
- `A8` (threat model) is refuted, and threat `I6` gets a measured fact: see the updated rows.

## Caveats and what is NOT shown

- Only two hooks, both stubs; only the scopes "flag settings" and "project local". The user-global and managed scopes, plugin and skill hooks, and hooks of other types (http, prompt, agent) are untested.
- Delays were 0 and 400 ms. How Claude Code orders hooks that finish within the same millisecond is not shown, only that such ties are not deterministic here.
- One Claude Code version (2.1.302), macOS, the Bash tool, an interactive session in a Python pty.
- It is not shown whether a newer Claude Code documents or changes this. A re-run is cheap if it does.
