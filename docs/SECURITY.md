# deskmates threat model

Status: draft v0.1, from the `agentic-council:Skeptic` agent's review. Design level only, no code was inspected. S = severity (C critical, H high, M medium).

| # | Risk | Failure scenario | S | Mitigation | Test |
|---|---|---|---|---|---|
| 1 | Browser reaches the allow/deny endpoint (CSRF, DNS rebinding, cross-origin WebSocket) | A malicious page POSTs to `localhost` or rebinds a hostname to 127.0.0.1 or opens a WebSocket and approves a dangerous command: remote code execution through the user's own agent | C | Bind 127.0.0.1 only. Reject any Host not exactly `localhost:PORT` or `127.0.0.1:PORT`. Check Origin on every HTTP and WS upgrade. Require a random per-run token in a custom header or WS subprotocol; no cookies. JSON only. Serve the token only to the same-origin page | Spoofed Host, `Origin: https://evil.com`, missing token, form-encoded POST must all fail; run a real rebinding harness |
| 2 | Approve/deny races and stale entries | Approval after the request timed out lands on the next request; double click sends two decisions; approval after Stop | H | Server-generated unique request id; state machine pending/decided/expired/superseded; atomic compare-and-set; bind decision to id plus hash of tool input; hook timeout shorter than Claude's; expiry means no decision (terminal prompt), never default allow | Decide twice, after timeout, after the agent moved on; two simultaneous requests; kill deskmates mid-request and confirm the terminal still prompts |
| 3 | Hook trust and fail-open or fail-closed | Writable hook script replaced by a repo; hung daemon blocks agents; a deny from deskmates overrides the user's own rules | H | Install script in a user-owned dir, mode 0700, record its hash. Hook is strictly additive (only "ask" or "no opinion", never allow what rules deny). Daemon down means exit 0 within 1-2 s. Default is report-only; approve-from-browser is explicit per-session opt-in with a visible banner | Daemon down, hung, returning garbage |
| 4 | Editing `settings.json` | Installer drops other hooks or comments; uninstall leaves a dead entry so every tool call errors; concurrent edit lost | H | Show a diff and ask for consent; timestamped backup; marker so only our entries are removed; self-healing command (script missing means exit 0); `deskmates uninstall` and `doctor`; prefer project-local or `--settings` over global; atomic write | Install then uninstall is byte-identical; install beside a foreign hook; delete script then run Claude |
| 5 | Secrets and private data reaching UI, logs, replays or clips | Transcripts hold `.env` contents, keys, customer data, usernames in paths; a shared clip shows a key | C (clips), H otherwise | Live UI shows minimum: never render `tool_result` bodies, only tool name and short label. Export is a separate allow-list pipeline. Redactor (key regexes, high-entropy strings, home path, `.env` patterns) before storing a replay and before every export, with a preview and "redacted N items" count. Never log raw content. Replay files mode 0600; store events, not full text | Seed fixtures with fake AWS, GitHub, Anthropic keys and a JWT; assert none appear in UI HTML, logs, replay JSON or exported frames |
| 6 | LAN or team mode exposure | Binding 0.0.0.0 without auth exposes prompts, paths and the approve button | C | Not in v1. Later: separate trust model with TLS, pairing codes, read-only by default, approve only locally, metadata only | Port scan from a second device; unauthenticated request; replayed token |
| 7 | Transcript format drift | A new Claude Code release renames fields; parser throws; office goes blank | H (certain) | Tolerant parser: unknown fields ignored, per-line try/catch, never crash the stream; record version per line; fixture corpus per version in CI; "format not recognized" badge instead of a wrong state | Fixtures from several versions; fuzz lines; canary against latest installed Claude Code |
| 8 | "No tool_result after N seconds" heuristic | A 10-minute build looks stuck or "needs you"; a real permission wait is missed; parallel calls confuse counts | H | Track open `tool_use` ids explicitly; label output "maybe waiting"; raise confidence only with a hook signal; per-tool thresholds; never notify from the heuristic alone | Fixtures: long Bash, parallel calls, lost result after crash, user interrupt; measure false positives on real history |
| 9 | File watching: huge files, partial lines, rotation | 500 MB file read whole; half-written last line skipped or double-counted; truncated or deleted file leaves a stale offset; thousands of old files exhaust watchers | H | Tail from byte offset; buffer until newline; key offset by inode plus size and re-read from 0 if it shrank; watch only recent sessions; cap line size; debounce | Writer appends a line in 3 chunks; truncate and delete during read; 1 GB synthetic file under a memory cap; run on the real projects folder |
| 10 | Session id collisions and same-project multi-session | Two terminals in one project become one desk; resumed session reuses id; wrong terminal approved | M (H for jump) | Key by (file path, sessionId); subagents are children linked by parent file; jump needs a reliable pid or tty from the hook payload, otherwise say "unknown" | Two concurrent sessions in one cwd; `--resume`; subagent ending after parent |
| 11 | Supply chain | A compromised dependency can read all transcripts and approve commands; native encoders add attack surface | H | Few dependencies, lockfile, pinned versions, no postinstall scripts, browser-native export, signed releases, `npm audit` and SBOM in CI, no telemetry and no network by default | Run the app with outbound network blocked in CI |
| 12 | XSS in the UI | Transcript text rendered as HTML next to the approve button | H | Render all transcript text as text, never innerHTML; strict CSP; approve needs a user gesture plus a token unreadable by injected markup; show the approval from the hook payload, not the transcript | HTML and script payload fixtures; CSP header check |
| 13 | Prompt injection through the approval UI | An LLM-written description says "safe" while the command is not | H | Show the raw command and arguments (truncated, "show full" option), never a paraphrase | Compare displayed vs actual payload on crafted inputs |

## What is most likely to make this fail

1. A security incident around the approve button. Ship passive and read-only first; add approve only after the token, Host and Origin checks pass the rebinding test.
2. Transcript format churn: a permanent maintenance tax. Tolerant parsing, fixtures, a "degraded" badge.
3. The wow factor wearing off. The Needs-you queue must be clearly faster than glancing at the terminal, which needs reliable notifications, which needs hooks, trust and consent.
4. Scope sprawl: replay, export, redaction, providers, team mode and approvals are separate products. Redaction alone is never finished. Sequence them (see `ROADMAP.md`).
5. Platform overlap: Anthropic or existing viewers may ship the same thing. Keep it small, fast and personal.

## Non-negotiables

- No state-changing endpoint without a per-run secret plus Host and Origin validation, tested against a real DNS-rebinding harness.
- Nothing is installed into the user's settings without a shown diff and explicit consent.
- No transcript content leaves the machine.
